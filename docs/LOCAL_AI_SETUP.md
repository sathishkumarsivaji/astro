# SKR ASTRO — Local Language Model Setup & Runtime Architecture

This guide provides instructions for configuring and running SKR ASTRO with a local language model. 

SKR ASTRO is engineered with a **local-AI-first, modular architecture**. Supported astrological queries, chart calculations, divisional charts (D1–D60), and prediction evaluations operate without requiring Google Gemini or any external cloud AI provider.

---

## 1. Zero Fabrication & Transparency Guarantees

1. **Epistemic Grounding**: Planetary positions, ascendants, houses, dashas, and transits are computed deterministically via high-precision astronomical ephemerides. The AI model is strictly constrained to syntactic intent classification (`QuestionSpecification`) and editorial phrasing of verified `AnswerObject` instances.
2. **Deterministic Fallbacks**: If no local model runtime is installed or reachable, SKR ASTRO automatically falls back to its deterministic rule engine.
3. **Explicit Inference Status**: All API and client responses explicitly label the inference mechanism:
   - `LOCAL_MODEL_SUCCESS`: Genuine response generated by the local language model.
   - `DETERMINISTIC_FALLBACK`: Generated by the deterministic rule and calculation engines (offline fallback).
   - `LOCAL_MODEL_UNAVAILABLE`: Local model runtime not detected or offline.
   - `LOCAL_MODEL_ERROR`: Local model returned an error or exceeded safety limits.
   - `EXTERNAL_PROVIDER_SUCCESS`: Generated via Google Gemini API (if explicitly enabled).
4. **Honest Evaluation**: Prediction precision is bounded by empirical evidence. Exact calendar dates and uncalibrated probabilities are redacted fail-closed by the Evidence Firewall.

## 2. Supported Local Model Runtimes

SKR ASTRO supports standard local inference servers via HTTP:

| Runtime | Default Endpoint | Compatibility | Notes |
| :--- | :--- | :--- | :--- |
| **Ollama** | `http://localhost:11434` | Native `/api/chat` & `/v1` | Recommended for straightforward CLI installation |
| **llama.cpp server** | `http://localhost:8080` | `/v1/chat/completions` | High performance GGUF execution |
| **LocalAI** | `http://localhost:8080` | `/v1/chat/completions` | Multi-backend support (ONNX/GGUF) |
| **vLLM / LM Studio** | `http://localhost:1234` | `/v1/chat/completions` | Desktop UI and fast batched inference |

## 3. Recommended Models

For reliable parsing of `QuestionSpecification` and bilingual (English / Tamil) answer rephrasing, the following quantized models are recommended:

| Model | Size | Recommended RAM | Context | Recommended Use |
| :--- | :--- | :--- | :--- | :--- |
| **Qwen 2.5 0.5B Instruct** (`qwen2.5:0.5b-instruct`) | ~400 MB | 1 GB | 4,096 | Fast intent parsing & mobile/low-memory environments |
| **Qwen 2.5 1.5B Instruct** (`qwen2.5:1.5b-instruct`) | ~1.1 GB | 2 GB | 8,192 | Balanced intent classification, Tamil support & wording |
| **TinyLlama 1.1B Chat** (`tinyllama:1.1b-chat`) | ~650 MB | 1 GB | 2,048 | Lightweight question classification |

## 4. Setup Instructions

### Option A: Using Ollama (Recommended)

1. **Install Ollama**:
   - Windows: Download from [ollama.com/download](https://ollama.com/download)
   - macOS: `brew install ollama`
   - Linux: `curl -fsSL https://ollama.com/install.sh | sh`

2. **Pull the Recommended Model**:
   ```bash
   ollama pull qwen2.5:1.5b-instruct
   ```
   Or for minimal resource usage:
   ```bash
   ollama pull qwen2.5:0.5b-instruct
   ```

3. **Verify Ollama is Running**:
   ```bash
   curl http://localhost:11434/api/tags
   ```

### Option B: Using llama.cpp server

1. Download a prebuilt `llama-server` binary for your platform.
2. Download a GGUF model artifact (e.g., `qwen2.5-1.5b-instruct-q4_k_m.gguf`).
3. Launch the server:
   ```bash
   ./llama-server -m models/qwen2.5-1.5b-instruct-q4_k_m.gguf --port 8080 -c 4096
   ```

## 5. Configuration & Environment Variables

Configure local AI settings in `backend/.env` or root environment:

```env
# Execution mode: LOCAL_FIRST (default), LOCAL_ONLY, DETERMINISTIC_ONLY, or CLOUD_OPTIONAL
LOCAL_AI_MODE=LOCAL_FIRST

# HTTP endpoint for the local model runtime
LOCAL_AI_ENDPOINT=http://localhost:11434

# Name of the active model in the local runtime
LOCAL_AI_MODEL=qwen2.5:1.5b-instruct

# Inference timeout in milliseconds (fail-closed if exceeded)
LOCAL_AI_TIMEOUT_MS=8000

# Cloud Gemini API key (optional; leave empty for purely local/offline operation)
GEMINI_API_KEY=
```

---

## 6. Verifying Local AI Operation

Run the built-in diagnostic and health check script:

```bash
node scripts/setup_local_ai.mjs
```

This diagnostic script:
1. Inspects local configuration and active execution mode.
2. Performs a health probe against `LOCAL_AI_ENDPOINT`.
3. Lists installed models from the runtime.
4. Checks the local `models/` folder for GGUF/ONNX artifacts and validates file integrity.
5. Executes an end-to-end question parsing check.
